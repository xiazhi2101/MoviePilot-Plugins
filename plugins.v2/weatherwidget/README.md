# 实时天气推送（WeatherWidget 自建版）

定时推送实时天气**卡片**（上方天气截图、下方带图标正文），并在 MoviePilot 仪表盘中显示实时天气。

自建版相对上游的主要变化：天气数据**优先走和风官方 API**，失败时自动回退网页抓取，
官网异常时也不会推送空内容；推送支持图文卡片，并可按实况生成出行建议。

> 上游原版：`InfinityPacer/WeatherWidget`（天气正文完全依赖抓取和风网页，
> 官网返回 5xx 时推送只剩标题、正文为空）。

---

## 一、安装

本插件位于本仓库的 `plugins.v2/weatherwidget/`，通过 MoviePilot **本地插件源**安装：

1. 在系统设置中确认 `PLUGIN_LOCAL_REPO_PATHS` 指向本仓库所在目录。
2. 插件市场刷新后搜索「实时天气推送」，安装即可。

安装后若发现版本被上游覆盖，可把运行目录下的文件替换为指向本地源的符号链接：

```bash
cd /app/app/plugins/weatherwidget
rm -f __init__.py
ln -s <本地插件源>/plugins.v2/weatherwidget/__init__.py __init__.py
```

## 二、和风天气 API 准备（强烈建议）

不配置 API 也能用（走网页抓取），但配置后数据更稳定、字段更全。

和风新版控制台采用「项目 → 凭据」两层结构：

1. 打开 [和风控制台](https://console.qweather.com/)，创建一个**项目**。
2. 在项目内创建 **API Key 凭据**（32 位字符串）。
3. 在项目设置中找到 **API Host**（形如 `xxxx.re.qweatherapi.com`），这是新版专属域名。

> 注意：旧版公共地址 `devapi.qweather.com` 配合新版 Key 会返回
> `401 Unauthorized` 或 `403 Invalid Host`，必须填自己的专属 Host。

插件已适配新版接口路径：

| 用途 | 接口 |
|---|---|
| 实时天气 | `/v7/weather/now` |
| 空气质量 | `/airquality/v1/current/{纬度}/{经度}`（旧 `/v7/air/now` 已废弃） |
| 生活指数（紫外线） | `/v7/indices/1d` |
| 三日预报 | `/v7/weather/3d` |
| 城市查询 | `/geo/v2/city/lookup`（旧 `/v2/city/lookup` 已 404） |

## 三、配置项说明

| 配置项 | 说明 |
|---|---|
| 启用插件 | 总开关 |
| 城市 | 展示用城市名，例如「陕西省咸阳市」；用于推送标题与截图文件名 |
| 城市链接 | 和风天气城市标识，例如 `xianyang-101110200`。<br>可在和风官网打开城市页，取 URL 末尾那段（`https://www.qweather.com/weather/xianyang-101110200.html`） |
| 和风天气 API Key | 上一步创建的凭据；留空则读取环境变量 `QWEATHER_API_KEY` |
| 和风天气 API Host | 专属 API Host，例如 `https://mk52qej9wd.re.qweatherapi.com`；留空用公共 Host（新版 Key 会失败） |
| 开启天气通知 | 是否定时推送 |
| 天气通知周期 | 5 位 cron 表达式，默认 `0 8,14,20 * * *`（每天 8/14/20 点） |
| 消息类型 | 通知渠道分类，例如「整理入库」 |
| 出行建议 | 是否在概述后追加一句出行提示（默认开启，可关闭） |
| 天气刷新周期 | 截图刷新间隔（小时）；设为「不刷新」则只推送通知、仪表盘不显示 |
| 显示边框 / 自动主题 / 自动高度 / 组件规格 / 适配方案 | 仪表盘显示相关 |

## 五、推送效果

企业微信会以 **news 图文卡片**呈现：上方是天气截图，下方是正文。

```
标题：【实时天气】- 咸阳 • 秦都
封面：天气截图（desktop 740×1024）

⏰时间: 2026-10-24 12:16
🌡️温度: 16°
☁️天气状况: 霾
🍃空气质量: AQI 129 轻度污染
🌬️东北风: 3级
💧相对湿度: 66%
🌡️体感温度: 14°
👁️能见度: 6km
🌧️降水量: 0.0mm
📊大气压: 961hPa
☀️紫外线: 弱

　　今天白天多云，夜晚多云，气温12~17°，现在16°；空气较差，敏感人群外出建议佩戴口罩。
```

要点：

- 概述段落首行缩进两个字符。
- 出行建议接在概述同一行，用「；」连接；内容按实况动态生成，
  优先级为：降水 → 霾/雾能见度 → 大风 → 昼夜温差 → 湿度 → 通用提示，只取最关键一条。
  若概述已表达同类信息（如已提到「空气较差」），建议会退回通用提示，避免重复。
- 标题按「城市」字段分层解析：同时含市与区时显示为「市 • 区」（如「咸阳 • 秦都」）；
  只有市显示「咸阳市」，只有区显示「秦都区」。想显示「咸阳 • 秦都」就把城市填为
  「陕西省咸阳市秦都区」。
- 卡片封面来自前端静态目录 `/public/weather_cover.png`，由 Nginx 免鉴权提供，
  因此企业微信服务器可以拉取。若 `APP_DOMAIN` 未配置或缺截图，会自动退回纯文本推送。

## 六、数据源与容错

1. 优先调用**官方 API**获取实况、空气质量、紫外线、三日预报。
2. 任一环节失败（鉴权、限流、官网故障）→ **自动回退网页抓取**。
3. 可选字段（空气质量、紫外线、三日预报）失败时**只跳过该字段**，不影响整体正文。

日志可据此判断走了哪条路径：

- `已通过官方 API 获取到天气信息` → API 路径
- `官方 API 未获取到天气，回退到网页抓取` → 网页路径
- `和风天气接口请求失败：HTTP xxx /xxx（可选接口，已跳过该字段）` → 可选字段缺失

## 七、常见问题

**Q：推送只有标题、没有内容？**
A：通常是网页抓取失败且 API 未配置。建议按第二节配置 API Key 与 Host。

**Q：API 返回 401 / 403？**
A：新版 Key 必须搭配专属 Host。检查「和风天气 API Host」是否填了自己控制台里的域名，
不要留空（留空会用公共 Host）。

**Q：卡片里截图不显示？**
A：检查系统是否配置了 `APP_DOMAIN`（外网可访问地址），以及插件数据目录下是否存在
`weather_*_desktop_*.png` 截图。截图由「天气刷新周期」控制，设为不刷新时不会生成。

**Q：配置保存后 API Key 或 Host 丢了？**
A：v3.5.0 已修复（改为从已保存配置回读补齐）。若仍遇到，重新填写一次即可。

**Q：为什么改了代码没生效？**
A：插件需要重载。若通过覆盖方式安装，注意运行目录可能被上游版本覆盖，
建议用符号链接指向本地插件源（见第一节）。
